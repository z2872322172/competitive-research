# 部署指南

## 一键启动（Docker Compose）

```powershell
docker compose up --build
# 或 start_demo.ps1
```

启动后：

| 服务 | 地址 | 说明 |
|---|---|---|
| 前端 | http://localhost:5173 | 容器内 4173（vite preview） |
| 后端 API | http://localhost:8000/v1 | FastAPI |
| MySQL | localhost:3306 | 库 verda / 用户 verda |
| Redis | localhost:6379 | Celery broker |
| Elasticsearch | http://localhost:9200 | 检索索引 |
| MinIO | http://localhost:9000（控制台 9001） | 产物存储 |

Compose 编排要点（根目录 `docker-compose.yml`）：

- `backend` / `worker` 使用 `APP_ENV=prod`：MySQL、`TASK_MODE=celery`、`ARTIFACT_STORAGE_BACKEND=minio`。
- `backend` 依赖 mysql / redis 健康检查通过后才启动；自身有 `/v1/health` 健康检查。
- `worker` 与 `backend` 共享 `backend-storage` 卷（MinIO 不可用时的本地降级存储）。
- 数据卷：`mysql-data`、`es-data`、`minio-data`、`backend-storage`。

## 生产部署要点

当前 MVP 阶段未做正式生产部署，以下为投入使用前必须处理的清单：

1. **密钥管理**：所有默认密码（MySQL verda/verda、MinIO minio/minio123）必须替换；`TAVILY_API_KEY` / `OPENAI_API_KEY` 通过环境变量或密钥管理注入，禁止入库入仓。
2. **用户鉴权**：P7-42 未实施。当前 `X-Workspace-Id` / `X-User-Id` 请求头不做校验，任何人可访问所有接口——对外部署前必须先补认证。
3. **HTTPS**：前端容器以 HTTP 提供，需在前面加反向代理（Nginx / Caddy）终止 TLS。
4. **数据库迁移**：当前靠 SQLAlchemy create_all 自动建表，schema 变更需引入 Alembic 迁移（backend/ 已含 alembic 骨架，见 backend/alembic.ini）。
5. **CORS**：`cors_origins` 默认只放行 localhost:5173，部署到其他域名需更新（`backend/app/config.py`）。
6. **备份**：MySQL 卷与 MinIO 卷需纳入备份策略（报告导出件与 HTML 快照都在其中）。

## 镜像构建

- 后端：`backend/Dockerfile`（Python 3.12 slim + requirements.txt）
- 前端：`frontend/Dockerfile`（Node 构建 + vite preview 运行；构建参数 `VITE_API_BASE_URL` 决定 API 地址，**镜像构建时固化**，改后端域名需重新构建镜像）

## 扩缩容参考

- `backend`（API）无状态，可水平扩展。
- `worker` 可多副本，Celery 任务按 run 粒度领取，checkpoint 保证重复执行安全。
- MySQL / Redis / ES / MinIO 为单实例编排，生产需自行集群化或使用托管服务。

## 环境矩阵

| | dev（本地默认） | prod（compose） |
|---|---|---|
| 数据库 | SQLite | MySQL 8.4 |
| 任务执行 | inline | celery + redis |
| 产物存储 | 本地 storage/ | MinIO（失败自动降级本地卷） |
| 搜索/LLM | 可选 Key | 需注入 Key |
