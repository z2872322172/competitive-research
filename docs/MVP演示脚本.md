# MVP 演示脚本

面向演示/验收的稳定操作流程：从创建任务到导出报告的完整闭环。全程无需任何 API Key（离线 demo 模式）；配置了 Tavily/LLM Key 时自动升级为真实采集与抽取，操作步骤不变。

## 演示前准备

```powershell
# 终端 1：启动后端（默认 dev 模式：SQLite + inline）
cd backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --port 8000

# 终端 2：启动前端
cd frontend
npm run dev
```

打开 http://localhost:5173 ，确认首页可访问；后端健康检查 `http://localhost:8000/v1/health` 返回 ok。

> 想演示真实搜索/LLM 能力：在启动后端前于 backend/.env 配置 `TAVILY_API_KEY` / `OPENAI_API_KEY`（参考《启动指南》）。下文步骤完全一致。

## 第一幕：创建研究任务（结构化输入）

1. 首页点「新建研究」。
2. 在需求描述里输入：`调研 Cursor 和 GitHub Copilot 的企业版定价与协作管控能力`。
3. 竞品填 `Cursor`、`GitHub Copilot`；维度选择「定价策略」「协作与管控」。
4. 不填手动 URL（走离线 demo 数据），直接提交。

**演示要点**：系统会解析需求生成结构化 scope（竞品 × 维度 × 检索策略），确认页展示规划结果——说明 Agent "听懂了"需求，而不是拿到一坨长 prompt。

## 第二幕：确认并启动研究

1. 确认页核对规划，点「确认并开始研究」。
2. 进入任务详情，观察**研究时间线**实时推进：规划 → 检索 → 抓取 → 解析 → 证据 → 结论 → 质检 → 报告。
3. 每个节点卡片有中文说明（该节点在做什么）、耗时、状态；活动流显示业务事件（发现来源/证据创建/结论创建）。

**演示要点**：失败恢复能力可现场演示——时间线上任一节点失败会有红色状态与「继续执行」入口（后台可随时用 resume 接口演示从 checkpoint 恢复）。

## 第三幕：证据墙与溯源（核心卖点）

1. 切到「证据库」标签：按竞品/维度/来源类型筛选证据。
2. 点开任一条证据：展示引文、locator（标题/字符区间）、质量分、抽取方式。
3. 点「查看快照」：看到来源的 HTML 快照摘要——**每条证据都能追溯到原始网页**。
4. 来源卡片展示原始 URL、canonical URL、publisher、抓取时间。

**演示要点**（可选，面向技术听众）：`GET /v1/sources/{id}/snapshot/raw` 返回原始 HTML 字节，响应头 `X-Artifact-Sha256` 可校验完整性——这是为将来知识库按引用取回文件预留的入口。

## 第四幕：Claim 人工审核

1. 研究完成后如有风险 Claim（低置信/冲突），任务进入 `waiting_review`，审核页高亮待处理项。
2. 演示三种决策：**接受**（纳入报告）/ **排除**（填写原因）/ **标记不确定**（入报告风险章节）。
3. 可用「批量接受低风险」一键处理高质量 Claim。
4. 全部处理完后触发**报告重新生成**（新版本，不覆盖旧版）。

**演示要点**：审核动作直接影响报告内容——排除的 Claim 不再出现，不确定的进入风险章节并降级标注。证据链不退化：无证据绑定的结论进不了报告。

## 第五幕：报告与导出

1. 报告页查看最新版本：执行摘要、关键结论（每条带证据引用）、风险章节、引用覆盖率。
2. 版本历史中切换旧版本对比。
3. 导出三种格式：**Markdown / PDF / DOCX**，下载到本地。
4. 每个章节下方展示引用的 Evidence 摘录与来源。

## 第六幕（可选）：失败与恢复演示

1. 另建任务，手动 URL 填一个不可达地址（如 `https://httpstat.us/500`）。
2. 观察单源抓取失败被跳过（任务不中断），时间线黄色警示。
3. 或演示取消：运行中任务点「取消」，状态变 canceled 且可重试。

## 常见演示故障

见《排障手册》。离线模式下搜索阶段提示"未配置 Key"属预期（走 demo 数据），不是故障。
