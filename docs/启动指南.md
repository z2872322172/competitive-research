# 启动指南

本文档面向开发者，描述如何在本地把项目完整跑起来。分为三种模式：本地开发（默认）、Docker Compose 一键启动、无外部依赖的最小验证。

## 前置要求

- Python 3.12+
- Node.js 20+
- （可选）Docker Desktop

## 模式一：本地开发（推荐日常使用）

### 1. 启动后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

- 默认 `APP_ENV=dev`：SQLite（`backend/verda_dev.db`）、`TASK_MODE=inline`（研究流程在 API 进程内同步执行）、本地文件存储（`backend/storage/`）。
- 启动成功后访问 `http://localhost:8000/v1/health` 应返回正常状态。
- 首次启动会自动建表（SQLAlchemy create_all），无需手动迁移。

### 2. 启动前端

```powershell
cd frontend
npm install
npm run dev
```

访问 `http://localhost:5173`。

### 3. （可选）配置真实能力 Key

不配置任何 Key 时系统使用 demo/规则 fallback，完整链路仍可跑通（见下方"最小验证"）。

**真实搜索（Tavily）：**

```powershell
$env:TAVILY_API_KEY = "tvly-..."
$env:SEARCH_PROVIDER = "tavily"
$env:SEARCH_MAX_RESULTS = "5"
```

**真实 LLM 抽取（OpenAI 兼容接口）：**

```powershell
$env:LLM_PROVIDER = "openai"
$env:LLM_BASE_URL = "https://api.openai.com/v1"
$env:LLM_MODEL = "chat-latest"
$env:OPENAI_API_KEY = "sk-..."
```

也可以写入 `backend/.env`（参考 `backend/.env.example`），该文件已被 gitignore。

### 4. 最小验证（无任何 Key）

创建任务时在 `source_preferences` 中手动提供 URL，即可走真实抓取/解析/证据/Claim/报告全链路：

1. 打开前端 `http://localhost:5173`
2. 新建研究任务，在来源偏好中粘贴一个或多个 `https://...` 页面链接
3. 确认任务，观察研究时间线推进
4. 查看证据墙 → 审核 Claim → 查看并导出报告

后端测试同样全部离线可跑：

```powershell
.\backend\.venv\Scripts\python.exe -m pytest          # 后端 95 条
cd frontend; Get-ChildItem src -Filter *.test.mjs | ForEach-Object { node --test $_.FullName }   # 前端 90 条
```

## 模式二：Docker Compose 一键启动

```powershell
docker compose up --build
# 或直接运行 start_demo.ps1
```

启动组件：backend、worker（Celery）、frontend、MySQL、Redis、Elasticsearch、MinIO。

- 前端：`http://localhost:5173`（容器内 4173 端口）
- 后端：`http://localhost:8000/v1`
- 此模式 `APP_ENV=prod`：MySQL 数据库、`TASK_MODE=celery`、MinIO 存储后端
- 首次拉起较慢（镜像构建 + 中间件健康检查），详见《部署指南》

## 模式三：Celery 异步模式（本地）

本地默认 inline 模式适合演示；验证异步模式需要 Redis：

```powershell
# 假设 Redis 已在 localhost:6379 运行
$env:TASK_MODE = "celery"
uvicorn app.main:app --reload --port 8000
# 另开终端启动 worker
celery -A app.workers.celery_app.celery_app worker --loglevel=info
```

## 环境配置速查

配置通过 `APP_ENV`（dev/test/prod）选择 profile，任何单项都可用环境变量覆盖，详见 `backend/app/config.py`。

| 用途 | 变量 | 默认（dev） |
|---|---|---|
| 环境 profile | `APP_ENV` | dev |
| 数据库 | `DATABASE_URL` | `sqlite:///./verda_dev.db` |
| 任务执行 | `TASK_MODE` | inline |
| 产物存储目录 | `ARTIFACT_STORAGE_DIR` | storage |
| 存储后端 | `ARTIFACT_STORAGE_BACKEND` | local（可选 minio） |
| 搜索 Key | `TAVILY_API_KEY` | 空（走 demo/手动 URL） |
| LLM Key | `OPENAI_API_KEY` / `LLM_API_KEY` | 空（走规则抽取） |
| Redis | `REDIS_URL` | redis://localhost:6379/0 |
| Celery Broker | `CELERY_BROKER_URL` | redis://localhost:6379/0 |

## 常见问题

- **Windows 下 pytest 报临时目录权限错误**：项目 pytest.ini 已固定 `--basetemp`，若复现请确认从项目根目录或 backend/ 目录运行。
- **前端请求 404 / 跨域**：确认后端在 8000 端口运行，前端 Vite 代理配置见 `frontend/vite.config.ts`，或通过 `VITE_API_BASE_URL` 指定后端地址。
- 更多问题见《排障手册》。
